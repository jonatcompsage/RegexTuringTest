String on the tape

Type, paste or drop any string. The machine decides one thing: is it a well-formed regular expression? It never runs the expression against text.

What the machine is doing

What the state names mean

A state is named after what the machine has just read, because that is all it remembers. “after (” means the last symbol was an opening parenthesis; “in [ ] after a-” means it is inside a character class and has just read a symbol and a dash. Click a name to show that state’s arrows in the graph.

    Grammar it decides
    regex      = alt
alt        = concat { "|" concat }
concat     = piece { piece }
piece      = anchor | atom [ quantifier ]
quantifier = ( "*" | "+" | "?" | count ) [ "?" ]
count      = "{" digits [ "," [ digits ] ] "}"
atom       = symbol | "." | escape | class | group
group      = "(" [ "?:" ] alt ")"
class      = "[" [ "^" ] item { item } "]"
item       = member [ "-" member ]
escape     = "\" ( d|D|w|W|s|S|t|n | metachar )
anchor     = "^" | "$"
metachar   = . * + ? ( ) [ ] { } | \ ^ $ - /

    A “]” straight after “[” or “[^” is a literal member. A set escape such as \d cannot be either end of a range. Everything but group is checked in pass 1; the recursion in group is what needs pass 2.

    Formal definition

    M = (Q, Σ, Γ, δ, q₀, qaccept, qreject). δ is the whole Table view. The tape is infinite in both directions and the machine always halts, so it is a decider.

        How this machine works

        The idea

        There is one machine and it never changes. Write a string on its tape and it halts in ACCEPT if the string is a well-formed regular expression, and in REJECT if it is not. It checks the shape of the expression only; it does not match it against anything.

        Why two passes

        Pass 1 sweeps right once. It checks every rule that only needs to remember what came just before: a quantifier has something to repeat, a class or repeat count is closed, an escape is known, no alternative is empty. A finite automaton could do all of this.

        Pass 2 is what a finite automaton cannot do. Groups nest to any depth, so the machine uses the tape as memory: it finds the rightmost “(” with no partner, marks it ⟨, walks right to the first unpaired “)”, marks it ⟩, and repeats. A “(” that finds no partner rejects; a “)” left over after the last sweep rejects.

        Parentheses that are only literals (escaped, or inside a class) are overwritten with • in pass 1 so that pass 2 does not count them.

        Reading the 3D graph

        • Each ball is a state; its colour is the job it does (key at the bottom left). The yellow ball is the current state.
        • The symbol goes on the arrow. Each arrow label says what the head reads, what it writes if it changes the cell, and which way it moves: read ( · write ⟨ · move R. “anything else” means every symbol the state does not list. To keep the graph readable, only the current state’s arrows are labelled; click a state (or its name in the left column) to see its arrows, or switch on All labels.
        • A state is named after what the machine has just read: “after (”, “got an atom”, “in [ ] after a-”. The list in the left column explains each one.
        • The thick yellow arrow is the rule about to fire. Arrows already used stay amber.
        • Arrows into REJECT are hidden until one fires (there are a great many); Reject arrows shows them all.
        • Drag to turn, wheel or pinch to zoom, right-drag, Shift-drag or two fingers to slide. Fit shows everything; Follow keeps the camera near the current state; Spin turns the graph slowly, which makes the depth easier to see.

        What it does not check

        • Meaning. [z-a] and a{5,2} have the right shape and are accepted; comparing the two ends is arithmetic, not grammar.
        • Features outside the grammar: backreferences, lookarounds, named groups and \b are rejected with a reason.
        • Symbols outside printable ASCII: δ has no entry for them, so the machine rejects.

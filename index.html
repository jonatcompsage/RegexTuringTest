      3D: drag to orbit, wheel or pinch to zoom, right-drag, shift-drag or two fingers to pan. Click a state in any view to toggle a breakpoint; Play pauses when the machine enters it. Every edge is drawn in the colour of the piece of the pattern that produces it (the same colour underlines that piece in the pattern box; grey edges come from more than one piece). In the 2D view a state is filled with the colour of the pattern piece that leads into it and drawn larger the more symbols it can accept; states the string has passed through get an amber ring. An arrow is drawn wider the more symbols it accepts, so a \d arrow (ten symbols) is visibly heavier than a single-character arrow. Click an edge to see its piece highlighted, or click a row of the token breakdown to emphasise the edges it produces. With Highlight on, every state and edge the string has passed through stays lit, so the whole path is visible. Per-symbol edges redraws the graph with one edge for each individual symbol (\d becomes ten edges, one per digit) instead of one edge per input class.
      
        
      The machine
      
        
      Your pattern is compiled to the minimal DFA and shown as a Turing machine. Other simulators leave three choices open; this one fixes them:
      
        
        
          
      • The tape is right-infinite. The input starts at cell 0 and is followed by blanks ⊔ forever; there is nothing to the left.
        • 
          
      • The head only moves right. It reads one cell, never writes, and moves one cell right on every step.
        • 
          
      • Halting is accept-or-reject only. Reading ⊔ in an accepting state accepts. Reading ⊔ anywhere else, or having no transition for a symbol, rejects. The machine cannot loop.
        • 
        
      
        
      Why are backreferences rejected? A pattern such as (a*)b\1 must remember how many a’s it saw, and that count has no upper limit. A finite machine has only its current state to remember with, so no finite machine recognizes that language: it is not regular.
      
      
      
      
      
        
      Supported grammar
      

      regex       = alternation
alternation = concat { "|" concat }
concat      = { quantified }
quantified  = atom [ quantifier ]
quantifier  = "*" | "+" | "?" | "{n}" | "{n,}" | "{n,m}"
              then an optional lazy "?" (ignored)
atom        = literal | "." | escape | class
            | group | anchor
group       = "(" [ "?:" ] alternation ")"
class       = "[" [ "^" ] { item | item "-" item } "]"
escape      = \d \D \w \W \s \S \t \n  or
              \ before one of . * + ? ( ) [ ] { } | \ ^ $ - /
anchor      = "^" at the start, "$" at the end (no-ops)
      
        
      Matching is always whole-string. Textbook notation: + is union, juxtaposition is concatenation, * is star, ε (or eps) is the empty string, ∅ (or null) the empty language, and every other character must be in Σ.
      
      
      
    
      
    
      Notes
      
    
        
      
      • Presets 1–20 are the Regex Explorer exercises rewritten as whole-string patterns: no \b, and a line-search exercise becomes “the whole line matches”. Exercise 20 only recognizes the “Last, First” shape; replacement is outside what a recognizer does.
        • 
      
      • The alphabet is printable ASCII plus tab and newline, so that \t, \n and \s are meaningful.
        • 
      
      • The classic pattern (b*ab*ab*)* does not accept “b” (each pass needs two a’s), so its minimal DFA has 4 states, not 2. The “Even number of a’s” preset therefore uses b*(ab*ab*)*, which is the 2-state machine. Its rejecting example is “abaa” (three a’s), because “aba” has two a’s and is accepted.
        • 
      
      • Edges into the sink are not drawn (they would hide the machine); they are listed in tooltips and in the Table view, and the edge taken is drawn in red when a run fails.
        • 
      
      • The parser reports the first grammar error it meets, not all of them at once.
